## What this is

An iOS Spotify listening-analytics app (top tracks/artists, recently played, listening stats).
SwiftUI + MVVM on the front end; Supabase (Postgres + Auth + Edge Functions + cron) on the back.

**Goals, in priority order:** (1) learn Swift via a real project, (2) practice senior-engineer
habits (clean architecture, tests, CI, docs), (3) a strong portfolio piece.

Scope for v1 is the essentials only: top tracks, top artists, recently played, listening-time stats.
No social features, no full history import.

## Architecture (the important decisions)

**Why a backend at all:** Spotify's API only returns top items over 3 fixed windows
(`short_term` ~4 weeks, `medium_term` ~6 months, `long_term` ~ past years — NOT true "all time")
and the **last 50** recently-played tracks. Real history and accurate "time listened" do not exist
in the API. So the backend continuously **collects** recently-played and stores every play; that
pipeline is the core of the product. Listening time is therefore an **estimate** (the API proves a
track was played and when, not that it was heard in full) and must be labeled as such. Stats start
at connection time and may have small gaps (heavy listening can overflow the last-50 window between
polls).

**Token ownership (the linchpin):** Supabase Auth does NOT persist or refresh Spotify provider
tokens — it returns them once at sign-in and forgets them. So we own them:
1. App signs in with Spotify (Supabase OAuth, PKCE).
2. App captures `provider_refresh_token` (treat as conditional; if missing, force fresh consent).
3. App sends it to the `store-spotify-credentials` Edge Function (the only writer of the
   service-role-only `spotify_credentials` table — the client never writes it directly).
4. The function encrypts it (AES-GCM) and stores it.
5. Backend mints fresh Spotify access tokens on demand (`refresh-spotify-token`) and inside the
   collector. Access tokens are **memory-only** on the device (never Keychain). The Supabase session
   is the only thing persisted on device (Keychain, via supabase-swift).

**Encryption details:** AES-GCM via WebCrypto in the Edge Functions. Key = Edge Function env secret
`TOKEN_ENCRYPTION_KEY` (32 bytes, base64). Per-encryption random 12-byte nonce (never reused). AAD
binds ciphertext to `user_id | key_version | "spotify_refresh_token"`. Columns: `key_version`,
`refresh_token_nonce`, `encrypted_at` support this and future key rotation. On Spotify
`invalid_grant`, the function sets `reauth_required = true` and stops, so we never hammer dead
tokens. If Spotify returns a rotated refresh token, we re-encrypt and overwrite.

## Backend specifics (Supabase)

- **Project ref:** `fplugrnakbwdjslpctrr`  (org: Renegade, region: us-east-2)
- **API URL:** `https://fplugrnakbwdjslpctrr.supabase.co`
- **Tables (migration in `supabase/migrations/`):**
  - `profiles` — owner-readable via RLS (`id`, `spotify_user_id`, `display_name`, `avatar_url`).
  - `spotify_credentials` — **service-role only** (RLS on, no client policies). Holds the encrypted
    refresh token + collector state (`last_collected_after_ms`, `last_success_at`, `last_error`,
    `token_refresh_failed_at`, `reauth_required`, `enabled`).
  - `play_events` — one row per observed play (denormalized track snapshot + `idempotency_key`
    unique). Owner-readable via RLS (select only); only the service role writes.
  - `collector_runs` — collector observability (status/counters/error summary per run).
    Service-role only.
  - (The `rls_enabled_no_policy` advisors on `spotify_credentials` / `collector_runs` are
    intentional.)
- **Edge Functions (`supabase/functions/`):**
  - `store-spotify-credentials` — OAuth handoff; encrypts + stores the refresh token.
  - `refresh-spotify-token` — mints a fresh access token; handles rotation + reauth.
  - `collect-plays` — the Phase 2 collector (see STATUS for deploy steps). Deploy with
    `--no-verify-jwt`; it is gated by the `x-collector-secret` header instead (constant-time
    compare against the `COLLECT_PLAYS_SECRET` Edge secret; fails closed if unset).
  - Shared code in `supabase/functions/_shared/` (`crypto.ts`, `spotify.ts`, `http.ts`,
    `plays.ts` — idempotency + row mapping, `secrets.ts` — constant-time compare,
    `credentials.ts` — the one mint-access-token flow: decrypt -> mint -> persist rotation ->
    flag `invalid_grant`; used by refresh-spotify-token AND collect-plays so the rotation/dead-
    token obligations can't drift apart).
  - Deno tests in `supabase/functions/_tests/` (`deno test --allow-env --no-lock _tests/` from
    `supabase/functions/`; CI runs them in the `backend` job).
- **Edge Function secrets that must be set** (in the dashboard): `SPOTIFY_CLIENT_ID`,
  `SPOTIFY_CLIENT_SECRET`, `TOKEN_ENCRYPTION_KEY`, `COLLECT_PLAYS_SECRET`.
- **Vault secrets** (Dashboard -> Project Settings -> Vault; read by `invoke_collect_plays()` at
  execution time): `collect_plays_url` = `https://<ref>.supabase.co/functions/v1/collect-plays`,
  `collect_plays_secret` = same value as `COLLECT_PLAYS_SECRET`.
- **Cron:** the migration schedules `collect-plays` every 10 minutes via `pg_cron` -> `pg_net` ->
  the wrapper `public.invoke_collect_plays()` (security definer, EXECUTE revoked from clients;
  warns + no-ops until the Vault secrets exist).
- **Idempotency-key scheme (LOAD-BEARING, do not change casually):** SHA-256 hex of canonical
  JSON — keys sorted, `played_at` normalized to epoch ms, `user_id` lowercased;
  `{played_at_ms, track_id, user_id}` for catalog tracks, falling back to
  `{artist_names (sorted), duration_ms, played_at_ms, track_name, user_id}` for local tracks.
  Pinned by an exact-hash test in `_tests/plays_test.ts`.
- Manage via the Supabase CLI (`supabase functions deploy`, `supabase db push`) or the Supabase MCP.

Spotify app's redirect URI must be `https://fplugrnakbwdjslpctrr.supabase.co/auth/v1/callback`, and
the Supabase Auth redirect allow-list must include `spotistats://login-callback`.

## After the spike passes — roadmap

**Phase 1 — Auth + live data.** Delete the spike screen. Build real navigation
(Home / Tracks / Artists). `AuthService` wraps the real sign-in + the `store-spotify-credentials`
handoff (with the nil-refresh-token fallback). `SpotifyAPIClient` (native `URLSession` + `Codable`,
protocol-based for testing) fetches top tracks/artists (label windows honestly) and recently played;
401 → refresh-and-retry-once; respect `429 Retry-After`. Decoding tests against JSON fixtures.
MVVM: one `@Observable @MainActor` view model per screen; loading/empty/error states.

**Phase 2 — Collector.** Add `play_events` + `collector_runs` tables. Denormalized track snapshot
(`track_id` nullable, `track_name`, `artist_ids[]`, `artist_names[]`, `album_name`, `album_art_url`,
`duration_ms`, `explicit`, `is_local`, `context_uri`, `played_at`, `idempotency_key`). Idempotency
key = hash of a canonical JSON object — `{user_id, played_at, track_id}`, falling back when
`track_id` is null to `{user_id, played_at, track_name, sorted artist_names, duration_ms}`. Indexes:
`(user_id, played_at desc)` and `(user_id, track_id)` up front; GIN on arrays only when needed.
`collect-plays` Edge Function scheduled via `pg_cron` + `pg_net` (invocation secret in Vault — note:
Vault is distinct from the Edge Function env secrets). Batches users, skips `reauth_required`, uses
the `after` cursor, upserts by `idempotency_key`, writes a `collector_runs` row, honors rate limits.

**Phase 3 — Stats.** SQL aggregation (views/RPC) for estimated listening time, counts, top-by-period,
trends. Stats screen with Swift Charts; everything labeled "estimated." Clearly separate Spotify's
affinity windows (top tracks/artists) from app-collected `play_events` stats.

**Phase 3.5 — Privacy & account control.** Settings: "Disconnect & forget credentials" (delete
stored token, disable collector; link to Spotify's "Apps with access" for true revocation) and
"Delete account" (`delete-account` function wipes all user data + the auth user). In-app data policy
+ `PRIVACY.md` (already in repo) with per-scope justification.

**Phase 4 — Polish.** AI-generated lo-fi night-city background scene with rain + smoke animated as
SwiftUI particle layers on top (the visual identity; smoke is a swappable element for age-rating
flexibility). Optional hardening: move interactive reads behind a `spotify-proxy` so the device never
sees a Spotify token. Broaden tests; finalize README + screenshots.
